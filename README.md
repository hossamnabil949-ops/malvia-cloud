# MALVIA Cloud — خادم المزامنة السحابي

يربط الكمبيوتر والموبايل: **ما يُسجَّل على أي جهاز يصل لباقي الأجهزة**، وكل جهاز يعمل أيضاً **دون إنترنت** ويرسل تغييراته عند عودة الاتصال.

## كيف يعمل (باختصار)
- لكل منشأة (عميل) **ملف قاعدة بيانات SQLite مستقل**: عزل كامل ونسخ احتياطي وتصدير سهلان لكل عميل.
- كل سجل له رقم تسلسلي على الخادم. الجهاز يرسل ما غيّره مع آخر رقم رآه؛ الخادم يقبله **فقط إذا لم يتغير السجل من جهاز آخر**، وإلا يُرجع النسخة الفائزة (فلا يضيع شيء بصمت).
- **سجل الرقابة للإضافة فقط** على مستوى الخادم: أي جهاز لا يستطيع تعديله أو حذفه.
- **الرصيد لا يُرسَل أصلاً:** يُحسب على كل جهاز من الحركات (افتتاحي + مشتريات − مبيعات + جرد)، فبيع جهازين لنفس الصنف في الوقت نفسه لا يُضيّع أي بيعة.
- **ترقيم الفواتير لكل جهاز** برمز (`INV-A-00001` من الكمبيوتر، `INV-B-00001` من الموبايل): لا يتكرر رقم.
- إعادة إرسال نفس التغيير بعد انقطاع الشبكة آمنة (لا تتكرر السجلات).
- نسخة احتياطية يومية لكل منشأة (آخر 14).

## التشغيل
```bash
cp .env.example .env     # ضع ADMIN_KEY طويلاً وعشوائياً
export $(grep -v '^#' .env | xargs)
node --no-warnings server.js     # Node 20 أو أحدث
node --no-warnings test.js       # اختبار ذاتي (13 اختباراً)
```
أو بـ Docker: `docker build -t malvia-cloud .` ثم `docker run -p 8788:8788 -v malvia-data:/data -e ADMIN_KEY=... malvia-cloud` (ملف Docker لم يُجرَّب في بيئة الإعداد).

## إنشاء منشأة
```bash
curl -X POST https://YOUR-SERVER/admin/tenants \
  -H "Authorization: Bearer $ADMIN_KEY" -H "Content-Type: application/json" \
  -d '{"name":"سوبر ماركت النور"}'
# يرجع "key" مرة واحدة فقط (mxc_...). يُحفظ مجزّأً ولا يمكن استرجاعه.
```
ثم في التطبيق على كل جهاز: **الإعدادات ← الربط السحابي** (أو من شاشة الإنشاء على جهاز جديد: «ربط هذا الجهاز بالسحابة») وأدخل عنوان الخادم والمفتاح. الجهاز الأول يرفع بياناته، وكل جهاز لاحق يستلمها.

## إدارة
| الطلب | الوظيفة |
|---|---|
| `GET /admin/tenants` | المنشآت وعدد سجلاتها وأجهزتها |
| `PATCH /admin/tenants/:id` `{"enabled":false}` | إيقاف منشأة |
| `GET /v1/devices` (بمفتاح المنشأة) | الأجهزة المرتبطة وآخر ظهور لكل منها |

## الاستضافة
الخادم عملية Node واحدة. شغّله على VPS أو منصة تدعم **قرصاً دائماً (Persistent Volume)**؛ بدون قرص دائم تضيع البيانات عند إعادة التشغيل. ضعه خلف **HTTPS** (Caddy أو Nginx أو ما توفره المنصة). لا تعرضه على HTTP.

## حدود يجب أن تعرفها قبل الإنتاج
1. **الأمان بمفتاح واحد للمنشأة:** من يملك المفتاح يستطيع المزامنة وقراءة كل بيانات المنشأة. **صلاحيات المستخدمين (مالك/مدير/كاشير) تُفرض في التطبيق فقط وليس في الخادم بعد**؛ كاشير بجهاز معدَّل يستطيع كتابة أي سجل. المطلوب لاحقاً: حسابات مستخدمين على الخادم وفرض الصلاحيات عليه.
2. بيانات المستخدمين (ومنها الرقم السري **مجزّأً**) تنتقل عبر الخادم لتعمل الأجهزة الجديدة بنفس الأرقام.
3. **تعارض التعديلات:** أول تعديل يصل يفوز، والجهاز الآخر يستلم النسخة الفائزة مع تنبيه. لا يوجد دمج على مستوى الحقول.
4. **بيع بالتوازي دون اتصال لآخر وحدة** من صنف قد يعطي رصيداً سالباً بعد الدمج (يظهر تنبيه نقص المخزون).
5. القاعدة SQLite على خادم واحد تكفي بدايات المشروع وعشرات المنشآت؛ عند النمو الكبير يُنقل التخزين إلى PostgreSQL (التصميم لا يتغير).
6. المزامنة تتم بالاستعلام الدوري (كل 20 ثانية وبعد كل تعديل)؛ لا دفع فوري ولا إشعارات خارجية بعد.
7. خادم الذكاء الاصطناعي (`malvia-gateway`) خدمة منفصلة وله عنوانه ومفتاحه في الإعدادات.
